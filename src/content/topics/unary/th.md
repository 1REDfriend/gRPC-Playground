# Unary RPC
> ส่ง request ไปหนึ่งก้อน ได้ response กลับมาหนึ่งก้อน หน้าตาเหมือนเรียกฟังก์ชันธรรมดา

Unary คือรูปแบบที่คุณจะได้ใช้บ่อยที่สุด ฝั่ง client เรียก `GetOrder` เหมือนเรียกฟังก์ชันในโปรเจกต์ตัวเอง ส่ง argument เข้าไปแล้วรอค่ากลับ ต่างกันตรงที่ตัวฟังก์ชันจริงไปรันอยู่บนอีกเครื่อง

แค่เรียกครั้งเดียว เบื้องหลังมี HTTP/2 frame วิ่งอยู่ห้าตัว client ส่ง HEADERS บอกว่าจะเรียก method ไหน ตามด้วย DATA ที่บรรจุ request ส่วน server ตอบกลับด้วย HEADERS แล้วก็ DATA ที่มี response และปิดท้ายด้วย TRAILERS ที่บอกว่าการเรียกครั้งนี้สำเร็จหรือพัง

> ลองกด “ทีละขั้น” แล้วคลิกแต่ละแถวในแผนภาพ ช่องด้านขวาจะแสดง header และ bytes จริงของ frame นั้น

## สิ่งที่ควรจำ

- path ของ method มาจาก `.proto` ตรง ๆ ในรูป `/<package>.<Service>/<Method>` อย่างในตัวอย่างคือ `/shop.v1.OrderService/GetOrder`
- message ทุกก้อนมีหัว 5 bytes นำหน้า byte แรกบอกว่าบีบอัดหรือเปล่า อีก 4 byte บอกความยาว
- ผลจริงของการเรียกอยู่ที่ `grpc-status` ใน trailers ถึง HTTP จะตอบ `200` การเรียกก็ยังล้มได้อยู่ดี
- แต่ละภาษามีสไตล์ของตัวเอง Go คืนค่าคู่กับ `error` Node.js ใช้ callback Python คืนค่าตรง ๆ ส่วน C# ใช้ `await`
- ตั้ง deadline ทุกครั้งที่เรียก (ในโค้ดตัวอย่างคือ 2 วินาที) เรื่องนี้มีบทแยกรออยู่ข้างหน้า
