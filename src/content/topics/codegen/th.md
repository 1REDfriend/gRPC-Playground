# Generate โค้ดจาก .proto
> เขียนสัญญาครั้งเดียว แล้วให้เครื่องมือสร้างโค้ด server กับ client ให้ทุกภาษา

ไฟล์ `.proto` เอาไปรันตรง ๆ ไม่ได้ ต้องผ่าน compiler ก่อน ตัวหลักชื่อ `protoc` ทำงานคู่กับ plugin ของแต่ละภาษา ผลที่ได้แบ่งเป็นสองกลุ่ม

- **โค้ดของ message** เป็น class หรือ struct ที่มี field ตรงกับ `.proto` พร้อมฟังก์ชันแปลงเป็น bytes และแปลงกลับ
- **โค้ดของ service** ฝั่ง server ได้ base class หรือ interface ที่มี method รอให้คุณเติม logic ส่วนฝั่ง client ได้ stub ที่เรียกใช้ได้ทันที

ตรงนี้แหละที่ gRPC ต่างจากการเขียน HTTP client เอง ถ้าใครเปลี่ยน `.proto` แล้วโค้ดคุณใช้ field ผิด compiler จะฟ้องตั้งแต่ตอน build ไม่ต้องรอไปพังบน production

===notes===

## เลือกเครื่องมือยังไงดี

- **protoc** ตรงไปตรงมา มีทุกที่ แต่คำสั่งยาวและต้องติดตั้ง plugin เอง
- **buf** อ่าน config จากไฟล์ `buf.gen.yaml` มีคำสั่ง `buf lint` ไว้ตรวจสไตล์ และ `buf breaking` ไว้เช็กว่าการแก้ `.proto` จะทำให้ client เก่าพังหรือเปล่า ทีมที่มีหลาย service มักย้ายมาใช้ buf
- **C#** ใช้ `Grpc.Tools` ที่ผูกเข้ากับ `dotnet build` เลย ไม่ต้องจำคำสั่งอะไรเพิ่ม
- **Node.js** มีทางเลือกเพิ่มคือโหลด `.proto` ตอนรันด้วย `@grpc/proto-loader` เริ่มต้นได้เร็ว แต่ type จะหลวมกว่า

## จัดโฟลเดอร์ให้ดี

วาง `.proto` ไว้ในโฟลเดอร์ตามชื่อ package เช่น `proto/shop/v1/shop.proto` แล้วใส่เลขเวอร์ชันใน package (`shop.v1`) วันที่ต้องแก้แบบ breaking จะได้เปิด `shop.v2` ขนานไปได้โดยไม่ทำให้ client เดิมพัง

หลายทีมเก็บ `.proto` ไว้ใน repo กลางแยกออกมา แล้วให้แต่ละ service ดึงไป generate เอง ทุกฝั่งจะได้ใช้สัญญาฉบับเดียวกันจริง ๆ
