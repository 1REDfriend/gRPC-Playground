# gRPC คืออะไร
> framework สำหรับให้โปรแกรมเรียกฟังก์ชันข้ามเครื่องกัน โดยมี schema เป็นสัญญากลาง

gRPC เป็น framework ที่ Google เปิดเป็น open source ในปี 2015 ตอนนี้อยู่ภายใต้ CNCF แนวคิดหลักเรียบง่ายมาก คุณเขียน `.proto` ไฟล์เดียวเพื่อบอกว่า service มี method อะไรบ้าง แต่ละ method รับและคืนข้อมูลหน้าตาแบบไหน จากนั้นเครื่องมือจะ generate โค้ดให้ทั้งฝั่ง server และ client ในภาษาที่คุณใช้

พอถึงตอนใช้งานจริง client เรียก `client.GetOrder(...)` ได้เหมือนเรียกฟังก์ชันในโปรเจกต์ตัวเอง เรื่องแปลงข้อมูลเป็น bytes เรื่องส่งผ่าน network และเรื่องแปลงกลับเป็น object ที่มี type ครบ ทั้งหมดนี้ gRPC จัดการให้

## ต่างจาก REST + JSON ตรงไหน

| | REST + JSON | gRPC |
|---|---|---|
| สัญญาระหว่าง client กับ server | เอกสาร หรือ OpenAPI (ถ้ามี) | `.proto` ที่ compile ได้จริง |
| รูปแบบข้อมูล | JSON เป็นข้อความ อ่านง่าย แต่ใหญ่ | Protobuf เป็น binary เล็กและ parse เร็ว |
| transport | HTTP/1.1 หรือ HTTP/2 | HTTP/2 เสมอ |
| streaming | ต้องไปพึ่ง WebSocket หรือ SSE | มีมาในตัว ทั้งสองทิศทาง |
| เรียกจากเบราว์เซอร์ | ได้ทันที | ต้องผ่าน gRPC-Web หรือ proxy |

ลองเลื่อนแถบด้านล่างดู ข้อมูล order ชุดเดียวกัน ถ้าส่งเป็น Protobuf จะเล็กกว่า JSON ราวสามเท่า

## gRPC เหมาะกับงานแบบไหน

- service คุยกันเองภายในระบบ (microservices) ที่ต้องการความเร็วและ type ที่ตรงกันทุกฝั่ง
- ระบบที่มีหลายภาษาปนกัน เช่น backend เป็น Go แต่ทีม data เขียน Python ทั้งสองฝั่งใช้ `.proto` ไฟล์เดียวกันได้
- งานที่ต้อง stream ข้อมูลต่อเนื่อง เช่น ติดตามสถานะ order แชต หรือส่ง log
- แอปมือถือที่อยากประหยัด bandwidth

แต่ถ้าเป็น API สาธารณะที่ให้ใครก็ได้ยิงจากเบราว์เซอร์หรือ `curl` REST ยังใช้ง่ายกว่า หลายทีมเลยใช้ทั้งสองแบบคู่กัน ข้างในคุยด้วย gRPC ส่วนข้างนอกเปิดเป็น REST

ทั้งเว็บนี้ใช้ `shop.proto` ข้างบนเป็นตัวอย่าง บทถัดไปจะแกะดูว่าข้างในไฟล์นี้มีอะไร
