# Bidirectional streaming
> ทั้งสองฝั่งส่งข้อมูลหากันได้อิสระบน stream เดียว ใครจะส่งก่อนหรือส่งกี่ครั้งก็ได้

ใส่ `stream` ทั้งฝั่ง request และ response ก็จะได้ bidirectional streaming (มักเรียกสั้น ๆ ว่า bidi) หน้าตาคล้าย WebSocket แต่ทุก message มี type ชัดเจนตาม `.proto`

```proto
rpc SupportChat(stream ChatMessage) returns (stream ChatMessage);
```

จุดที่คนมักเข้าใจผิดคือคิดว่าต้องผลัดกันพูด ถามหนึ่งตอบหนึ่ง จริง ๆ แล้วไม่ใช่ ฝั่งอ่านกับฝั่งเขียนแยกจากกันเด็ดขาด ในแผนภาพจะเห็นว่า server ทักก่อนได้ ตอบสองข้อความติดกันก็ได้ และมีช่วงที่ทั้งสองฝั่งส่งสวนกันพร้อมกันด้วย

ตอนจบก็แยกกัน client half-close เมื่อไม่มีอะไรจะพูด แต่ server ยังส่งต่อได้ stream จะปิดจริงก็ตอนที่ server ส่ง trailers

===notes===

## สิ่งที่ควรจำ

- ฝั่ง client มักต้องแยกงานอ่านกับงานเขียน เช่น goroutine ใน Go, `Task` ใน C# หรือ event handler ใน Node.js ถ้าเขียนแล้วรออ่านในบรรทัดเดียวกันอาจติด deadlock ได้
- ลำดับ message **ในทิศทางเดียวกัน** รับประกันว่าไม่สลับ แต่ข้ามทิศทางไม่มีการรับประกันว่าอะไรมาก่อน
- ใน Python `from` เป็นคำสงวน ต้องใช้ `**{"from": ...}` หรือ `getattr` ตอนตั้งชื่อ field ใน `.proto` เลยควรเลี่ยงคำสงวนของภาษาที่ทีมใช้
- งานที่เหมาะ เช่น แชต, เกมออนไลน์, ระบบ sync ข้อมูลสองทาง, งาน speech-to-text ที่ส่งเสียงเข้าไปพร้อมกับรับข้อความกลับมา
